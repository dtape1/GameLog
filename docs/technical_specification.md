# Технічне завдання (Technical Specification)
## Проєкт: GameLog

## 1. Загальна інформація

**Назва проєкту:** GameLog  
**Тип проєкту:** Веб-додаток  
**Технології:** Python, Django, SQLite  
**Команда:** Ільчук, Дорощенков, Пахольчук  

---

## 2. Мета проєкту

Метою проєкту є розробка веб-додатку для ведення щоденника геймера з можливістю додавання ігор, оцінювання, коментування та взаємодії між користувачами.

---

## 3. Функціональні вимоги

Система повинна забезпечувати:

### 3.1 Робота з користувачами
- реєстрація користувача
- авторизація (логін)
- вихід з акаунту
- перегляд профілю користувача

### 3.2 Робота з іграми
- перегляд списку ігор (List Page)
- пошук ігор
- фільтрація ігор за статусом
- сортування (за рейтингом, датою)

### 3.3 Детальна сторінка гри (Detail Page)
- перегляд інформації про гру
- відображення середнього рейтингу
- відображення коментарів

### 3.4 Взаємодія користувача з іграми
- додавання гри до бібліотеки
- встановлення статусу (хочу пройти / проходжу / пройшов / кинув)
- виставлення оцінки
- додавання нотаток

### 3.5 Коментарі
- створення коментаря
- видалення власного коментаря
- перегляд коментарів інших користувачів
- лайки до коментарів

### 3.6 Профіль користувача
- список ігор користувача
- статистика (кількість ігор, середній рейтинг)

### 3.7 Головна сторінка
- відображення топ ігор (за рейтингом та кількістю оцінок)

### 3.8 Адміністративна частина
- управління іграми
- управління користувачами
- модерація коментарів

---

## 4. Нефункціональні вимоги

- система повинна працювати у браузері
- інтерфейс має бути зрозумілим та простим
- дані повинні зберігатися у базі даних
- система повинна підтримувати кількох користувачів
- час відповіді системи не повинен перевищувати кількох секунд

---

## 5. Обмеження

- використовується Django та Python
- база даних — SQLite
- без використання складних фронтенд-фреймворків
- реалізація тільки базового функціоналу без перевантаження

---

## 6. Критерії прийняття

Проєкт вважається виконаним, якщо:

- працює реєстрація та авторизація
- реалізовано List Page та Detail Page
- реалізовано додавання ігор та оцінювання
- працюють коментарі
- реалізовано ролі User та Admin
- є зв’язки в базі даних (1-1, 1-N, M-N)
- працює пошук та фільтрація
- проєкт розміщено на GitHub

---

## 7. UML діаграми(в репозиторії буде візуалізація)

### 7.1 Use Case (варіанти використання)

Користувач:
- реєструється
- входить в систему
- додає гру
- ставить оцінку
- пише коментар
- переглядає профілі

Адміністратор:
- керує іграми
- керує користувачами
- видаляє коментарі

---

### 7.2 Діаграма класів

Основні сутності:

- User
- Profile
- Game
- Comment
- UserGame

Зв’язки:
- User → Profile (1:1)
- Game → Comment (1:N)
- User ↔ Game (через UserGame)

---

### 7.3 Діаграма послідовностей

Приклад: додавання гри

1. Користувач обирає гру
2. Вводить дані (статус, оцінка)
3. Дані передаються у сервер
4. Дані зберігаються у базі
5. Відображається результат
